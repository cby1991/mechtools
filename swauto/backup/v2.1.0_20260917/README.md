# SWauto —— SolidWorks 一键导出（模型 → STEP，工程图 → PDF）

一个 SolidWorks VBA 宏：**把模型另存为 .stp/.step，把它对应的工程图另存为 .pdf**。
运行时会弹出输出目录选择框，**默认定位到上次使用的目录**。

**主入口"看当前激活的文档自动决定导出范围"**：零件就导这一个零件；装配体就把它下面的零件展开导一遍 ——
**螺钉螺母等标准件、以及隐藏 / 压缩 / 封套的零件自动过滤**；装配体 / 子装配体自身不导出，只交付零件。

---

## ⭐ 只记一件事：运行 `SwAuto_ExportActiveDoc`

> **打开要导出的零件 / 装配体 → 运行 `SwAuto_ExportActiveDoc` → 选输出目录 → 完成。**

它会自己看你打开的是什么，然后决定导什么：

| 你打开的 | 它导出 |
|---|---|
| 零件 `.sldprt` | 就导这一个零件（STEP + 它对应工程图的 PDF） |
| 装配体 `.sldasm` | 把它下面的**零件**导出来。装配体/子装配体自身不出；自动跳过：螺钉螺母等标准件、隐藏/压缩/封套的零件 |
| 工程图 `.slddrw` | 导这张图 + 它引用的模型 |

**四个宏，编号就是模式**（编号会出现在**每一个弹窗的标题上**）：

| 宏 | 弹窗标题里的标识 | 什么时候用 |
|---|---|---|
| `SwAuto_ExportActiveDoc` | **1/3 · 当前文档** | ⭐ 平时只用这个 |
| `SwAuto_PickFiles` | **2/3 · 自选文件** | 只想导我挑出来的那几个（会先弹"选文件"框） |
| `SwAuto_PickFolder` | **3/3 · 文件夹批量** | 整个文件夹批量（会先弹"选源文件夹"框） |
| `SwAuto_Help` | （说明弹窗） | 忘了该绑哪个宏、忘了怎么绑 → 运行它，会告诉你 |

> **模式编号是干什么用的**：如果你按快捷键，弹出来的却是【3/3 · 文件夹批量】，
> 那就说明**快捷键绑到了 `SwAuto_PickFolder`**，不是代码坏了 —— 回第 2.3 节重绑一次即可。
> 弹窗标题里带模式标识，就是为了让这种"绑错宏"在按下的一瞬间就暴露出来。

| `dist/SWautoExport_粘贴用.txt` | 同一份代码的 **UTF-8 版**，给"打开→全选→复制→粘贴到 VBE"用（剪贴板是 Unicode，不受代码页影响，最保险） |

| `backup/v1.0.0_20260916/` | v1 的完整快照 |
| `backup/v2.0.2_20260916/` | v2.0.2 的完整快照（"装配体展开 + 标准件过滤"已实测可用的版本） |

> 备份目录只作留存回退用，**别在里面继续改代码** —— 每一版的 `build.py` 只会拼当前 `src/` 的内容。

改动源码后重新生成导入文件：

```
python build.py && python check.py
```

## 2. 安装（一次性）

### 2.1 先删掉旧的
如果之前导入过旧版本，先清理：VBE 左侧工程窗口里右键那个模块 → **移除 Module**（不要点"导出"）。

### 2.2 两种导入方式，任选一种

**方式 A：导入文件（推荐）**

1. SolidWorks → 菜单 **工具 > 宏 > 新建**，文件名随便起（如 `SwAutoExport`），保存到固定位置，例如
   `C:\Users\<你>\AppData\Roaming\SolidWorks\SOLIDWORKS <版本>\Macros\`。SolidWorks 会自动打开 VBA 编辑器。
2. VBA 编辑器里：**文件 > 导入文件…** → 选择 `dist/SWautoExport.bas`。
3. **Ctrl+S 保存**。宏工程存成 `.swp`，下次启动 SolidWorks 自动可用。

> ⚠️ `dist/SWautoExport.bas` 是 **GBK 编码**，这是刻意的：VBE 导入 `.bas` 时按**系统 ANSI 代码页**解码
> （简体中文 Windows = GBK）。如果写成 UTF-8，中文会全部乱码，而且中文标点的字节会**吞掉后面的结束引号**，
> 直接报"编译错误：语法错误"。详见第 8.1 节。

**方式 B：复制粘贴（最保险，不受代码页影响）**

1. 用记事本 / VS Code 打开 `dist/SWautoExport_粘贴用.txt`（UTF-8，中文正常显示）。
2. 全选复制。
3. SolidWorks → 工具 > 宏 > 新建 → VBE 里双击 `模块1` → 全选原有内容后粘贴 → Ctrl+S。

### 2.3 绑一个快捷键（⚠️ 这一步有个大坑，务必看完）

**这是最容易出错的一步**，因为它藏着一个不起眼的【方法】下拉框。

**工具 > 自定义 > 键盘** → 左上"类别"选 **`宏`**：

- **如果「命令」列里已经有这个宏** → 选中它 → 在"请输入新的快捷键"框里按组合键（比如 `Ctrl+Shift+E`）→ 点 **指派**。
- **如果「命令」列里没有** → 点那行 **`新建宏按钮`** 右侧的 `…` → 在「**操作**」里浏览到你的 **`.swp`**
  （就是第 2.2 节存下来的那个宏工程，通常在 `…\AppData\Roaming\SolidWorks\SOLIDWORKS <版本>\Macros\`）
  → **★ 然后在同一行的「方法」下拉框里，选 `SwAuto_ExportActiveDoc` ★** → 确定 → 再按上面的方式指派快捷键。

> ⚠️ **「方法」这个下拉框千万别漏**。
> 一个 `.swp` 宏工程里可以有很多个可运行的过程（我们这个模块有 4 个），
> 而 SolidWorks 必须知道"这个快捷键到底要跑哪一个"。**不选，它就会自己挑一个** ——
> 挑到的很可能不是 `SwAuto_ExportActiveDoc`，于是你按快捷键，弹出来的却是
> 【3/3 · 文件夹批量】那个"请选择要导出的源文件夹"。
> **这不是 bug，是绑定没指定方法。** 回上面重绑一次就好。

想放工具条：同一对话框的"工具栏"页 → 新建一个工具栏 → 把同一个宏拖上去（同样要选「方法」）。

**绑完怎么验证**：按一下快捷键，看弹窗**标题** ——
标题是 `SWauto v2.1.0　1/3 · 当前文档` 就对了；是 `3/3 · 文件夹批量` 就说明绑错了。

> 若编译报**"用户定义类型未定义"**：VBE → **工具 > 引用** → 勾选
> `SldWorks <版本> Type Library` 与 `SOLIDWORKS <版本> Constant type library`。

### 2.4 VBE 里按 F5 会弹出一个"宏"列表？那是正常的

在 VBA 编辑器里，如果光标**不在任何过程内部**，按 `F5`（或 运行 > 运行子过程）时，
VBE 会弹出「宏」对话框让你挑一个过程来跑 —— 因为一个模块里有多个可运行的过程，它无法替你决定。

这个列表里除了本工具的 4 个入口，**可能还有你自己以前录制的宏**（比如 `filterx`）。
列表乱、容易挑错，建议：

1. VBE 左侧「工程资源管理器」里，把**与 SWauto 无关的模块**右键 → **移除**（只留 SWauto 那一个模块）；
2. 要调试本工具，不用 F5 挑列表，直接在代码里把光标点进**要跑的那个过程内部**，再按 `F5`；
3. 日常使用**完全不需要打开 VBE** —— 用快捷键或工具条按钮就够了。

## 3. 四个入口宏

| 入口 | 模式标识 | 行为 |
|---|---|---|
| `SwAuto_ExportActiveDoc` | **1/3 · 当前文档** | **主入口，看当前激活的文档自动决定**（详见下表） |
| `SwAuto_PickFiles` | **2/3 · 自选文件** | 弹原生文件对话框**多选**文件（`.sldprt/.sldasm/.slddrw`）后排入队列逐个导出。**只想导一部分文件时用这个。** |
| `SwAuto_PickFolder` | **3/3 · 文件夹批量** | 弹文件夹对话框，**批量导出整个文件夹**（是否含子目录由 `CFG_RECURSE_SUBDIR` 控制）。当前开着文档时会先确认一次（默认按钮是"否"）。 |
| `SwAuto_Help` | — | 使用说明：宏一览 + 绑快捷键的方法 + 当前打开的文档。**忘了哪个宏该绑快捷键就运行它。** |

### 3.1 主入口 `SwAuto_ExportActiveDoc` 的行为

| 当前激活的是 | 导出什么 |
|---|---|
| **零件** `.sldprt` | 本零件的 STEP ＋ 它对应工程图的 PDF |
| **装配体** `.sldasm` | **展开它下面所有零件**，每个零件各出一份 STEP ＋ 对应的工程图 PDF。**装配体本身和各级子装配体不导出**（配置 5.2 可改回） |
| **工程图** `.slddrw` | 本图的 PDF ＋ 它引用的模型的 STEP |

**装配体展开时有两道自动过滤**（按顺序执行）：

| 顺序 | 筛掉什么 | 判定方式 | 开关 |
|---|---|---|---|
| ① | **隐藏 / 压缩 / 封套**的组件 | `Component2::IsHidden` / `IsSuppressed` / `IsEnvelope`，**沿父级链向上判定** | 第 5.3 节 |
| ② | **标准件**（螺钉螺母垫圈…） | Toolbox 标记 / 路径 / 文件名 / 国标号 | 第 5.4 节 |

被跳过的组件**都不会静默消失**：清单里会写清楚是谁、因为什么被跳过，汇总弹窗和确认框也会报个数，不会让你觉得"东西莫名其妙少了"。

**每次运行都会先弹输出目录选择框**（默认上次用过的目录），确认框里会写清楚"模型 N 个、工程图 M 个、已过滤标准件 K 个"，点确认才开始。

### 3.2 工程图是怎么找到的？

复刻 SolidWorks「打开工程图」的查找顺序，三级递进：

1. 模型同目录下的**同名** `.slddrw`；
2. `CFG_EXTRA_DIRS` 里配置的搜索目录中的同名 `.slddrw`；
3. **反查引用关系**：扫描目录里的工程图，用 `GetDocumentDependencies2` 读出它引用了哪些模型
   （这个接口**不需要打开文件**，所以很快），建立 `模型 → 工程图` 索引。批量时索引只建一次。

三级都没找到，不会静默跳过——会写进清单的**"以下模型未找到对应工程图"**段落，并在汇总弹窗里列出来。

## 4. 输出结构

**默认 STEP 和 PDF 放在同一个目录**（`CFG_USE_SUBFOLDER = False`），省得来回找：

```
<你选的输出目录>\
├─ A支架.STEP
├─ A支架.PDF
├─ 底板.STEP
├─ 底板.PDF
└─ _导出清单.csv            本次运行的完整明细
```

想按类型分开，把 `CFG_USE_SUBFOLDER` 改成 `True`，就会变成 `STEP\` 和 `PDF\` 两个子目录。

`_导出清单.csv`（UTF-8 BOM，Excel 直接双击可读）开头是统计摘要，然后是明细表：

`序号, 类别, 源文件, 输出文件, 结果, 备注` —— 结果取值 `成功 / 跳过 / 失败`，备注里是错误码或原因；
文件末尾单独列出**被过滤掉的标准件**和**未找到对应工程图的模型**。

> 注：不同目录下的同名零件（比如两个都叫 `底板.sldprt`）会**自动加序号**避免互相覆盖，清单的"输出文件"列能看到实际写到哪儿了。

## 5. 配置区（文件第 1 节，改完保存即可）

### 5.1 输出与查找

| 常量 | 默认 | 说明 |
|---|---|---|
| `CFG_STEP_AP` | `203` | STEP 协议，可用 `203` 或 `214`（AP214 会带颜色/图层） |
| `CFG_USE_SUBFOLDER` | `False` | **`False`＝STEP 和 PDF 放同一个目录**；`True`＝分 `STEP\`、`PDF\` |
| `CFG_OVERWRITE` | `True` | `False` 时同名文件跳过并计入清单 |
| `CFG_FIND_DRAWING` | `True` | 模型导出后是否自动找它的工程图 |
| `CFG_DRW_ALSO_MODEL` | `True` | 处理工程图时是否把它引用的模型也导出 STEP |
| `CFG_DEEP_SEARCH` | `True` | 同名找不到时是否反查引用关系 |
| `CFG_DEEP_LIMIT` | `1500` | 深搜最多扫多少个工程图，防超大目录卡死 |
| `CFG_EXTRA_DIRS` | `""` | 额外搜索目录，多个用 `;` 分隔 |
| `CFG_RECURSE_SUBDIR` | `False` | 文件夹模式是否递归子目录 |
| `CFG_WRITE_REPORT` | `True` | 是否生成 `_导出清单.csv` |
| `CFG_USE_PS_DIALOG` | `True` | 多选文件用 PowerShell 原生对话框 |
| `CFG_QUIET_OPEN` | `True` | 静默打开文档，不弹配置/参考丢失对话框 |

### 5.2 装配体展开（第 1.5 节）

| 常量 | 默认 | 说明 |
|---|---|---|
| `CFG_ASM_EXPAND` | `True` | `True`＝装配体展开导出内部所有零件；`False`＝只导装配体本身（想回到"只导总装"的老行为就改这里） |
| `CFG_ASM_SELF` | **`False`** | 展开时，装配体本身与各级子装配体是否也各出一份 STEP。**默认 `False`＝只交付零件**：装配体 / 子装配体自身、以及它们的工程图都不导出。改成 `True` 可以连带把它们也导出来 |

### 5.3 装配体展开时的"参与状态"过滤（第 1.7 节）

这三种组件在装配体里都**不参与当前的设计状态**，导出它们只会污染交付物，所以默认全部跳过：

| 常量 | 默认 | 跳过什么 |
|---|---|---|
| `CFG_SKIP_HIDDEN` | `True` | **已隐藏** 的零件 |
| `CFG_SKIP_SUPPRESSED` | `True` | **已压缩** 的零件 |
| `CFG_SKIP_ENVELOPE` | `True` | **封套** 零件（只作空间占位参考的体） |

三条要点：

1. **沿父级链判定**：某个子装配体被隐藏 / 压缩时，它下面的零件也一起跳过
   （子零件自身往往是"显示"的，但实际跟着父级一起看不见）。
2. **轻化不算**：轻化（Lightweight）只是加载方式，零件本身有效，**照常导出**。
   > 这条在代码里靠 `IsHidden(False)` 实现。`IsHidden` 的参数**必须传 `False`** ——
   > 传 `True` 时它会把"压缩"和"轻化"一并算成隐藏，**轻化零件会被整批误杀**。
   > 自检脚本里有一条专门拦这个写法的检查，改错了跑 `python check.py` 就会报警。
3. **状态是配置相关的**：可见性随**当前激活的配置**变化，这里过滤的是运行那一刻的实际状态。
   同一个装配体换个配置再跑一次，结果可能不同 —— 这是符合预期的，不是 bug。

> 同一个零件在装配体里可能有**多个实例**，状态各不相同。宏的处理是"**只要有一个可见实例，这个零件就导出**"，
> 并且会撤销掉那条矛盾的"跳过"记录，所以清单里不会出现"一边成功、一边跳过"的怪现象。

### 5.4 标准件过滤（第 1.6 节）

`CFG_EXCLUDE_STD_PARTS` 默认 `True`。命中下面**任意一条**就判定为标准件并跳过：

| 规则 | 配置常量 | 默认值 |
|---|---|---|
| ① SolidWorks 官方 Toolbox 标记 | `CFG_STD_USE_API` | `True` |
| ② 文件路径含关键字 | `CFG_STD_PATH_HINTS` | `SOLIDWORKS Data,Toolbox,标准件,紧固件` |
| ③ 文件名含关键字 | `CFG_STD_KEYWORDS` | 螺钉/螺母/螺栓/垫圈/挡圈/销/铆钉…（中英文） |
| ④ 文件名含标准号 | `CFG_STD_STDCODES` | `GB/T,GB-T,GBT,ISO,DIN,JIS,ANSI,BS-` |

**关键字怎么匹配（这套规则是为了"该认的认出来、不该认的别误伤"）：**

| 关键字长什么样 | 匹配方式 | 例子 |
|---|---|---|
| 含中文 | 直接子串匹配 | `内六角螺钉M8x30`、`螺母M8` 都能认出（← 尺寸代号紧贴在后面也不影响） |
| 含 `/` `-` `_` 空格等 | 直接子串匹配（自带边界） | `GB/T`、`GB-T`、`Spring Pin`、`O-Ring` |
| 纯字母数字 | **词边界**匹配 | `Spindle` 不中 `Pin`、`Walnut` 不中 `Nut`、`ISOLATION` 不中 `ISO`、`Screwdriver` 不中 `Screw`；但 `GBT5782`、`ISO4762`、`Nut8` 能中 |

改完关键字后**跑一下 `python check.py`** —— 里面有一节"标准件关键字规则抽检"，会用 16 个"必须命中"和 14 个"绝不能命中"的用例验一遍，立刻告诉你有没有加错。

想放行某一类，把对应关键字从列表里删掉即可；整个功能不想用就把 `CFG_EXCLUDE_STD_PARTS` 改成 `False`。

上次用过的目录记在注册表
`HKCU\Software\VB and VBA Program Settings\SWauto\Export`，键 `LastOutputDir` / `LastInputDir`。
想重置就删掉这个键。

## 6. 注意事项与已知限制

- **不做任何源文件的改动**，所有输出都是"另存"，源文件时间戳不变。
- **STEP AP 是全局用户选项**：宏调用 `SetUserPreferenceIntegerValue(swStepAP, 203)` 会改掉
  `工具 > 选项 > 系统选项 > 导出 > STEP` 里的设置（这是 SolidWorks API 的既定行为）。
  如果写入没生效，清单备注里会写明"AP203 未能写入用户选项，已按当前选项导出"。
- **PDF 的线宽、颜色、字体、黑白**遵循 `工具 > 选项 > 系统选项 > 导出 > PDF`；
  多张图纸默认合并成**一个** PDF（`ExportAsSinglePDF = True`）。
- **两种自动过滤（隐藏/压缩/封套、标准件）只在"当前激活的是装配体"时生效**。
  `SwAuto_PickFiles` / `SwAuto_PickFolder` 是你明确挑出来的文件，一律照导，不会替你过滤 ——
  理由很直接：那两个模式没有装配体上下文，无从判断"隐藏"。
- **兜底通道不做状态过滤**：万一装配体连打开都失败，宏会退回去读文件依赖表
  （`GetDocumentDependencies2`，不需要打开文档）。那条路拿不到组件对象，所以**判断不了隐藏/压缩/封套**，
  只能做标准件的路径和文件名判定。它只在主通道完全失效的异常情况下才会走到。
- 装配体里的**虚拟零件**（几何存在装配体内部、没有独立文件的那种）没法单独另存成 STEP，
  会写进清单（结果 `跳过`，备注"虚拟零件"），不会静默丢掉。
- **超大装配体可能慢**：状态过滤要对每个组件调 3 个属性、再沿父级链回溯一次。
  上千个组件的装配体首次展开可能要等几秒到几十秒，属正常。嫌慢可以把 `CFG_SKIP_*` 里的开关按需关掉。
- 批量导出时 SolidWorks 界面会短暂无响应，这是宏单线程执行导致的，属正常现象；文件多的目录请耐心等汇总弹窗。
- 深搜反查依赖工程图里记录的引用路径。如果图纸引用的是**已换盘符 / 已改名**的旧路径，反查会落空——
  这种情况请用同名规则，或把图纸所在目录加进 `CFG_EXTRA_DIRS`。
- 多选文件对话框依赖 Windows 自带的 PowerShell + .NET WinForms；若被安全策略拦截，会退化成"没有选中文件"，
  此时改用 `SwAuto_PickFolder` 或 `SwAuto_ExportActiveDoc`。
- 装配体导出前会调用 `ResolveAllLightWeightComponents` 还原轻化零件，避免导出空几何；展开遍历也是先还原再取组件，
  否则轻化状态下会漏件。

## 7. 建议的第一次试跑

**第 0 步（新增）：验证快捷键绑对了没。** 按一下快捷键，看弹窗标题：
出现 `SWauto v2.1.0　1/3 · 当前文档` 才算绑对；出现 `3/3 · 文件夹批量` 就回第 2.3 节重绑。
这一步花 5 秒，能省掉后面所有"怎么导的不是我要的"的困惑。

1. **开一个零件**，运行 `SwAuto_ExportActiveDoc` —— 应该只出 1 个 STEP（和它的 PDF，如果有图）。
2. **开一个小装配体**（3～5 个零件，里面最好带几个 Toolbox 螺钉，并**故意隐藏一个普通零件**），运行同一个宏 —— 确认：
   - 装配体和子装配体本身**没有**出现在输出目录里；
   - 螺钉螺母没被导出，**被隐藏的那个零件也没被导出**；
   - 确认框、汇总弹窗、清单三处都能看到"跳过了几个、为什么"；
   - 其余每个零件都出了 STEP，有图的出了 PDF；
   - 打开 `_导出清单.csv`，"结果"列没有非预期的 `失败`，末尾两段能看到被跳过的东西和原因。
3. 确认无误后，再去处理正式的大装配体。

## 8. 故障排查

### 8.1 导入后满屏乱码 + 编译报"语法错误"

**同一件事的两个症状，根因是文件编码。** VBE 导入 `.bas` 时按**系统 ANSI 代码页**解码。
简体中文 Windows 的代码页是 936(GBK)，所以：

- 把 UTF-8 的文件当 GBK 读 → 所有中文变成 `璇ユ枃浠跺す` 这种乱码；
- 更致命的是：中文标点（例如「。」的 UTF-8 字节是 `E3 80 82`）的收尾字节 `82`、`83`
  在 GBK 里属于**前导字节**，会跟紧随其后的 ASCII 字符（往往就是字符串的结束引号 `"` 或连接符 `&`）
  合成一个汉字 —— **引号被吃掉了**，字符串没有结尾，于是报"语法错误"。

**处理办法**：删掉出错的那个模块，按第 2.2 节重新导入（现在的 `dist/SWautoExport.bas` 已经是 GBK 编码）。
如果还不行，说明这台机器的 ANSI 代码页不是 936，请改用**方式 B 复制粘贴**，那条路不经过代码页，必定正确。

### 8.2 编译报"用户定义类型未定义"

VBE → 工具 > 引用 → 勾选 `SldWorks <版本> Type Library` 和 `SOLIDWORKS <版本> Constant type library`。

### 8.3 运行时报"SldWorks 未定义"或宏列表里找不到入口

入口宏必须是 `Public Sub` 且**不带参数**。列表里只会出现 `SwAuto_` 开头的四个。
如果四个都没有，说明模块没编译通过，先解决编译错误。

### 8.4 按快捷键却弹出了【3/3 · 文件夹批量】（"请选择要导出的源文件夹"）

**不是代码问题，是快捷键没指定「方法」。** 原因和修法都在第 2.3 节：

**工具 > 自定义 > 键盘 > 类别`宏`** → 找到绑定这个快捷键的那一行 → 删掉快捷键 →
重新用「新建宏按钮」绑一次，**在「方法」下拉框里明确选 `SwAuto_ExportActiveDoc`**。

判定依据很简单：**看弹窗标题**。绑对的话标题一定是 `1/3 · 当前文档`。
`SwAuto_PickFolder` 现在也会在你开着文档时先弹一个确认框（默认按钮是"否"），
所以就算绑错了，误扫整个文件夹这种情况也不会直接发生。

### 8.5 装配体展开了，但漏了零件 / 数量不对

按可能性排序：

1. **它被"参与状态"过滤掉了**（v2.1.0 起）—— 零件在装配体里是**隐藏 / 压缩 / 封套**状态。
   去看清单末尾"以下组件因【隐藏 / 压缩 / 封套】被跳过"那段，会写明是哪个、为什么。
   这是宏**故意**不导的；确实要导，就把它在装配体里显示出来，或者到配置第 1.7 节关掉对应开关。
2. **它被当成了标准件**—— 去看清单末尾"以下零件被判定为标准件而跳过"那段。误判就到配置第 1.6 节删关键字。
3. **组件是轻化状态** —— 宏已经先调 `ResolveAllLightWeightComponents` 还原，但如果还原失败（比如沙箱模式下没权限），
   会退回到"读文件依赖表"的兜底通道。看清单里的实际条数。
4. **是虚拟零件**（存在装配体内部、没有独立文件）—— 会记在清单里（备注"虚拟零件"），
   不是丢了，是物理上没法单独另存。
5. **它是装配体/子装配体本身** —— v2.1.0 起默认不导出，这是刻意的（配置 5.2 `CFG_ASM_SELF`）。

### 8.6 输出目录里出现了 `零件_2.STEP` 这种重复文件

`_2` 后缀是宏的**防覆盖**机制：本次运行里有**两个不同路径**想输出成同一个文件名时，第二个自动加序号。
它被触发，说明同一个零件被收录了两遍。原因通常是：**工程图里记录的模型引用路径，跟你扫描到的不是同一种写法**
（旧位置 / 相对路径 / 大小写差异），而反查逻辑（`CFG_DRW_ALSO_MODEL`）把图纸引用的模型又带了一遍。

**v2.0.1 已经修掉了这个**，三层拦截：

1. 反查只认「**绝对路径 + 文件真实存在**」—— 挡掉 `.\零件.SLDPRT` 这类相对路径形式的"名称项"
   （`GetDocumentDependencies2` 返回的是「名称 + 全路径」成对数据，那个"名称"有时自带 `\`，
   老版本只判断"含不含 `\`"，就会把它当成第二条独立路径收进来）；
2. 反查追加时，如果主列表**已经有同名模型**就不再追加；
3. 导出前按规范化路径判重，**同一个物理文件本次只会导一次**（清单里记为"跳过 / 本次已导出过"）。

**如果还看到 `_2`**：那多半不是 bug，而是**真的有两个不同目录的同名零件**，这时 `_2` 恰恰是对的。
打开 `_导出清单.csv` 看"源文件"列 —— 两个文件来自哪里一目了然。

### 8.7 我的标准件没被过滤掉 / 我的正常零件被误过滤

这两个是同一个旋钮的两端，都在配置**第 1.6 节**：

- **没过滤掉**：说明文件名和路径里都不含现有关键字，也不带 Toolbox 标记。
  把该公司常用的命名特征加进 `CFG_STD_KEYWORDS`（比如你们把螺钉命名成 `SHCS`，就加上 `SHCS`）。
- **误过滤**：把命中的那个关键字从 `CFG_STD_KEYWORDS` / `CFG_STD_STDCODES` 里删掉。
  清单备注会写清楚**是哪条规则、哪个关键字**命中的（例如"文件名含 螺钉"），照着删就行。

### 8.8 清单里某些工程图"失败：无法打开工程图"

工程图引用的模型路径失效（换过盘符 / 手工改过名 / 网络盘未连接）。
先在 SolidWorks 里手工打开一张确认，或者在 `工具 > 选项 > 系统选项 > 文件位置` 里补上搜索路径。

### 8.9 清单备注里出现"AP203 未能写入用户选项"

说明这台机器的 SolidWorks 没能被写进该用户选项（权限或版本差异）。
到 `工具 > 选项 > 系统选项 > 导出 > STEP` 手工把协议设为 AP203 即可，其余功能不受影响。

### 8.10 多选文件对话框点了没反应

`SwAuto_PickFiles` 走的是 PowerShell + .NET WinForms 的原生对话框。
如果被安全策略拦截，会退化成"没有选中文件"。改用 `SwAuto_PickFolder` 或 `SwAuto_ExportActiveDoc`。

### 8.11 隐藏的零件还是被导出了 / 正常零件被当成"隐藏"跳过了

**该跳的没跳**：先确认配置第 1.7 节的 `CFG_SKIP_HIDDEN` / `CFG_SKIP_SUPPRESSED` / `CFG_SKIP_ENVELOPE`
没被你关掉。三个都是 `True` 才生效。

**不该跳的跳了**，按顺序排查：

1. **那个零件在那个配置下确实是隐藏/压缩的** —— 可见性随**当前激活的配置**变化，
   你可能在另一个配置下看它"显示"过。运行时以激活的那个配置为准。
2. **是它的上级子装配体被隐藏了** —— 零件自身显示，但跟着父级一起跳过。
   清单备注里会带 **"（上级装配体）"** 字样，看到这个就说明是父级的问题，不是零件本身。
3. **不是轻化的锅** —— 代码里特意用 `IsHidden(False)` 避开"轻化被误判成隐藏"这个坑
   （`IsHidden(True)` 会把轻化也算成隐藏）。所以零件被跳过，一定不是因为它轻化。

### 8.12 装配体 / 子装配体的 STEP 和图纸不见了

v2.1.0 起**这是默认行为**，不是 bug：`CFG_ASM_SELF` 默认改成了 `False`，
因为交付通常只需要零件，装配体自身的 STEP 和它对应的工程图 PDF 属于噪音。

想连带导出来，把配置第 1.5 节的 `CFG_ASM_SELF` 改成 `True` 即可。
